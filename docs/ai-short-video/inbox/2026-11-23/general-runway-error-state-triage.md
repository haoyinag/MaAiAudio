# 通用技巧：先按错误状态分流再改提示或换模型

- **主维度：** `general`
- **来源 URL：** https://help.runwayml.com/hc/en-us/articles/32880432736659-Why-am-I-receiving-errors-when-trying-to-generate
- **发布机构 / 作者：** Runway
- **发布日期：** 页面未标明
- **采集日期：** 2026-11-23（Asia/Shanghai）
- **来源等级：** 模型平台官方帮助中心
- **核验状态：** `单一来源`
- **适用平台 / 地区：** Runway；其他平台仅借鉴分流结构
- **时效：** 高；错误分类与积分规则可能变化

## 来源明确事实

1. Runway 将使用政策拦截与生成错误分开处理：前者要求修改被标记的提示或素材，重复提交同一被拦截内容可能导致账号暂停。
2. 生成错误常见输入原因包括素材分辨率过低或过高、提示与参考素材冲突，以及不支持的文件格式或画幅。
3. 对持续失败，官方建议调整输入、换模型定位；第三方模型错误可能因诊断信息有限而更模糊。

## 分析推断

“失败”不能统一重试。先区分政策拦截、输入/规格错误、模型错误和成片完成但不合格，可避免把合规问题误当抽卡问题；换模型首先用于定位故障域，不代表必然达到质量门槛。

## 可执行含义

1. 任务账本保存错误类型、错误原文、模型、提示版本、参考素材版本和规格。
2. 政策拦截先审内容与权利，不原样连点；生成错误先核分辨率、格式、画幅和提示/参考冲突，再做单变量重试。
3. 同输入持续失败后换一个模型定位；若跨模型失败，优先回到输入资产和规格层。

## 已知困境与边界

- 官方未给出各错误原因发生率或最大重试次数，不能据此设通用废片率。
- 本条不覆盖“任务成功但画面不可交付”的质量返工。
- 与既有“输入净化”“单变量迭代”互补；新增错误状态分流和重复政策拦截的账号边界。
