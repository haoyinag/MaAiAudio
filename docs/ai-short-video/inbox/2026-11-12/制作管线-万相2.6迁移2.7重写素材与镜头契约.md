# 制作管线：万相 2.6 迁移 2.7 要重写素材、镜头和音频契约

- **主维度：** `pipeline`（制作管线）
- **来源 URL：** https://help.aliyun.com/zh/model-studio/wan-video-to-video-api-reference
- **补充来源 URL：** https://help.aliyun.com/zh/model-studio/text-to-video-prompt
- **发布机构 / 作者：** 阿里云百炼官方文档
- **发布日期：** 页面未标明；2026-11-12 核验当前版本
- **采集日期：** 2026-11-12（Asia/Shanghai）
- **来源等级：** 模型厂商官方 API 与提示词文档
- **核验状态：** `已核验`
- **适用平台 / 地区：** 阿里云百炼万相参考生视频 API，wan2.6 → wan2.7
- **时效：** 高；接口字段、默认值和模型版本易变

## 来源明确事实

1. wan2.7 不再用 `character1`、`character2` 引用角色，改为按素材类型和顺序使用“图 n / 视频 n”（英文为 `Image n / Video n`）。
2. wan2.7 不支持 `shot_type`；多镜头改由提示词里的总体描述、镜头序号、时间戳和分镜内容控制。
3. 请求结构从 `reference_urls` 字符串数组改为带 `type`、`url` 的 `media` 对象数组；分辨率字段从 `size` 改为 `resolution`。
4. wan2.7 默认生成有声视频，不再要求像 wan2.6 那样显式设置 `audio`。`reference_voice` 可为参考图 / 视频主体指定音色；若参考视频自带音频又传入 `reference_voice`，后者优先。

## 分析推断

- 这不是只替换模型名的升级：素材索引、分镜控制、分辨率和音频默认值同时改变，旧请求即使能改到可调用，也可能产生静默行为变化。
- 迁移验收应把“请求可成功”与“角色、镜头、声音符合旧基线”分开。

## 可执行含义

1. 建立字段迁移表：`characterN → 图n/视频n`、`reference_urls → media[]`、`size → resolution`，删除 `shot_type`。
2. 把原多镜头配置改写为带镜头序号和时间戳的 prompt，并逐镜对照旧版本基线。
3. 对每个任务显式记录是否需要音频；检查参考视频原声与 `reference_voice` 的覆盖优先级，避免意外换声。
4. 用一组固定样片做迁移回归：角色绑定、镜头数 / 顺序、分辨率、台词、音色和静音需求。

## 与既有条目的关系

- **增量：** 在 2026-10-30 万相 3 能力边界与 2026-11-10 多镜头故事板字段之外，新增可执行的 2.6 → 2.7 API 迁移契约。
- **不替代：** 不替代万相 3.0 的当前能力记录；本条只处理 wan2.7 参考生视频迁移与回归。
