# 制作管线：Runway Workflow 用版本端点固化生产链

- **主维度：** `pipeline`（制作管线）
- **来源 URL：** https://dev.runwayml.com/learn/pipeline-as-an-endpoint
- **发布机构 / 作者：** Runway
- **发布日期：** 2026-10-26
- **采集日期：** 2026-11-13（Asia/Shanghai）
- **来源等级：** 模型厂商官方开发文档
- **核验状态：** `已核验`
- **适用平台 / 地区：** Runway Workflows / Runway Dev；全球，以账号和用量等级为准
- **时效：** 极高；端点、模型可用性、计费与限额可变

## 来源明确事实

1. Runway Workflow 可将多模型节点图发布为私有 API 端点；一次请求运行图像、视频、语言模型和剪辑节点，输出从同一 invocation 读取。
2. 每次发布生成独立版本 ID；旧版 ID 仍保留，集成方通过更换 ID 决定何时迁移，重新发布不会自动改变现有集成。
3. 运行结束为 `SUCCEEDED` 时仍可能有部分节点失败，官方要求同时检查 `nodeErrors` 和预期输出；输出 URL 会在 24–48 小时后失效，需另存要保留的成果。
4. 官方明确不建议在需条件分支、循环重试、人工审批或逐请求换模型时使用固定 Workflow；这些逻辑应留在代码或 Model Router 中。

## 分析推断

- 可重现的生产管线需锁定“工作流版本 + 模型版本 + 输入 + 节点错误”，不能只保存最终视频。
- 视觉节点图适合固定链路，但不应吞掉质检重试、费用中止和人工审批。

## 可执行含义

1. 每次变更提示、模型或节点时发布新版，先用固定回归样本验收，再切换配置中的版本 ID。
2. 成功判定同时检查总状态、`nodeErrors`、必需输出、成本与归档结果。
3. 把需要人工审批、内容质检后重试或动态选模型的部分留在外层编排。

## 与既有条目的关系

- **增量：** 既有 Runway Agent 条目讲“先审计划再消耗积分”；本条新增发布后的版本端点、节点错误检查和不适合固定工作流的边界。
