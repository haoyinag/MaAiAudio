# 制作管线：Firefly 故事板生成首帧前冻结画幅与分辨率

- **主维度：** `pipeline`
- **来源 URL：** https://helpx.adobe.com/firefly/web/work-with-audio-and-video/work-with-video/build-a-story.html
- **发布机构 / 作者：** Adobe Firefly Help
- **发布日期：** 2026-11-10（页面更新时间）
- **采集日期：** 2026-11-20（Asia/Shanghai）
- **来源等级：** 模型厂商官方文档
- **核验状态：** `单一来源`
- **适用平台 / 地区：** Adobe Firefly Web `Video > Build a story` beta；具体可用地区与账户以产品页为准
- **时效：** 极高；Beta 能力和限制可能变化

## 来源明确事实

1. Build a story 会把创意组织为场景与镜头卡，先生成帧，再逐卡或批量生成视频，并可转入时间线继续编辑。
2. 官方当前限制写明：项目生成帧后，不能再改变任何镜头的分辨率和宽高比。
3. 该 Beta 仅支持 Chrome / Edge，不支持移动 Web 或小于 1080×700 的视口；本地片段不能直接上传到卡片，只能从 Adobe 云存储的生成历史添加。

## 分析推断

- 画幅和分辨率不是末端导出选项，而是生成首帧前的项目级不可逆决策。未先确认分发矩阵就批量生成，会把返工扩大到整套镜头卡。

## 可执行含义

1. 建项目先冻结主平台、画幅、安全区和目标分辨率；需要 9:16 与 16:9 时建立两个项目或先做小样验证迁移方案。
2. 只生成 1–2 张代表性镜头帧，检查主体裁切、字幕安全区和构图后，再执行 `Generate all`。
3. 本地素材先规划进入 Adobe 云生成历史的路径；没有可追溯上传路径时，不把该 Beta 设为唯一生产管线。

## 已知困境与边界

- Beta 限制可能变化；批量开工前必须复核帮助页和当前账户界面。
- 官方没有承诺跨项目复制能保留全部镜头设置，也没有提供返工成本数据。
- 与既有“先审计划再批量生成”互补；新增的是生成帧后的项目设置锁定边界。
